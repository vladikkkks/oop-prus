# Звіт до самостійної роботи №23
**Тема:** Adapter + Facade + Proxy: кеш і ліміти.
**Варіант:** №12 (Обробка подій).

## Контрольні питання

### 1. Поясніть патерн Adapter. Коли його слід використовувати?
**Adapter (Адаптер)** — це структурний патерн, який дозволяє об'єктам із несумісними інтерфейсами працювати разом. Його слід використовувати, коли ви хочете скористатися стороннім або застарілим класом, але його інтерфейс не відповідає коду вашої програми.

### 2. Поясніть патерн Facade. Як він спрощує роботу зі складними підсистемами?
**Facade (Фасад)** — надає єдиний спрощений інтерфейс до групи класів, бібліотеки або великої підсистеми. Він спрощує роботу, приховуючи складність взаємодії між багатьма об'єктами. Замість того, щоб змушувати клієнта викликати методи 5-ти різних сервісів у правильному порядку, клієнт викликає один метод фасаду.

### 3. Поясніть патерн Proxy. Наведіть приклади різних типів Proxy.
**Proxy (Заступник)** — підміняє собою реальний об'єкт для контролю доступу до нього.
* **Virtual Proxy:** Створює реальний об'єкт лише тоді, коли він справді потрібен (ледаче завантаження).
* **Protection Proxy:** Перевіряє права доступу (авторизація).
* **Logging/Caching Proxy:** Зберігає результати запитів або записує історію викликів.
* **Rate-Limit Proxy:** (як у нашому коді) обмежує частоту викликів до об'єкта.

### 4. У чому полягає ключова відмінність між Adapter, Facade та Proxy?
* **Adapter** змінює інтерфейс об'єкта, щоб зробити його сумісним з іншим.
* **Facade** створює *новий спрощений інтерфейс* для цілої підсистеми, не змінюючи старі.
* **Proxy** реалізує *той самий інтерфейс*, що й реальний об'єкт, але додає логіку контролю/обробки "навколо" виклику.
