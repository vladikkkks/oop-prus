# Контрольні питання до самостійної роботи №19

### 1. Поясніть патерн Factory Method. Які проблеми він вирішує?
**Factory Method (Фабричний метод)** — це породжувальний патерн проектування, який визначає загальний інтерфейс для створення об'єктів у суперкласі, але дозволяє підкласам змінювати тип створюваних об'єктів.

**Проблеми, які він вирішує:**
*   **Жорстка залежність (Tight Coupling):** Позбавляє необхідності прив'язувати код до конкретних класів продуктів. Клієнт працює з абстракціями (інтерфейсами).
*   **Принцип відкритості/закритості (OCP):** Дозволяє додавати нові типи продуктів у програму, не змінюючи вже існуючий клієнтський код.
*   **Дублювання коду:** Централізує логіку створення об'єктів в одному місці.

### 2. Поясніть патерн Singleton. Коли його доцільно використовувати, а коли варто уникати?
**Singleton (Одинак)** — патерн, який гарантує, що клас має лише один екземпляр, і надає глобальну точку доступу до цього екземпляра.

*   **Доцільно використовувати:**
    *   Для керування спільними ресурсами (доступ до бази даних, логування, сервіс генерації ID).
    *   Коли створення об'єкта є дуже ресурсомістким і він має бути в системі в єдиному екземплярі.
    *   Для зберігання глобальних налаштувань програми.
*   **Варто уникати:**
    *   У модульному тестуванні (Unit Testing), оскільки Singleton створює глобальний стан, що заважає ізоляції тестів.
    *   Коли порушується "Принцип єдиної відповідальності" (клас і виконує свою роботу, і сам контролює свій життєвий цикл).
    *   У багатопотокових середовищах без належної синхронізації (може створитися два об'єкти).

### 3. Як ці два патерни можуть працювати разом для створення гнучкої та контрольованої системи?
Поєднання цих патернів дозволяє створити архітектуру, де:
1.  **Singleton** (наприклад, `IdService`) виступає в ролі єдиного диспетчера або менеджера, який доступний з будь-якої частини програми.
2.  **Factory Method** дозволяє цьому менеджеру динамічно змінювати стратегію або тип створюваних об'єктів залежно від контексту чи налаштувань.

Це дає контроль над життєвим циклом сервісу (через Singleton) та гнучкість у виборі конкретних реалізацій інструментів (через Factory Method).

### 4. Які переваги дає використання абстракцій (інтерфейсів) у поєднанні з Factory Method та Singleton?
*   **Інверсія залежностей (DIP):** Код високого рівня (клієнт) не залежить від деталей реалізації низького рівня (конкретних генераторів або логерів).
*   **Легкість тестування:** Замість реальних об'єктів (наприклад, реальної бази даних) у фабрику можна підставити "заглушки" (Mocks), які реалізують той самий інтерфейс.
*   **Масштабованість:** Можна легко замінити один алгоритм іншим (наприклад, замінити `RandomIdGenerator` на `SecureCryptoGenerator`), просто створивши нову фабрику, при цьому інтерфейс взаємодії залишиться незмінним.
