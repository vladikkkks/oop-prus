# Звіт до самостійної роботи №22
**Тема:** Composite + Decorator: реалізація та форматування.
**Варіант:** №12 (Фінансові транзакції).

## Контрольні питання

### 1. Поясніть патерн Composite. Як він дозволяє працювати з ієрархічними структурами?
**Composite (Компонувальник)** дозволяє згрупувати об'єкти у деревоподібну структуру. Він забезпечує уніфікований інтерфейс для окремих об'єктів (листя) та цілих гілок (контейнерів). Завдяки цьому клієнтському коду не потрібно знати, чи працює він з одним елементом, чи з цілою групою — операція викликається однаково, а контейнер сам делегує її своїм нащадкам.

### 2. Поясніть патерн Decorator. У чому його перевага над наслідуванням для розширення функціональності?
**Decorator (Декоратор)** дозволяє динамічно додавати нову поведінку об'єкту, "загортаючи" його в спеціальні класи-обгортки.
* **Гнучкість:** На відміну від наслідування, яке є статичним, декоратори можна комбінувати в будь-якому порядку під час виконання програми.
* **Уникнення розростання ієрархії:** Замість створення підкласів для кожної комбінації властивостей (наприклад, `TransactionWithFeeAndCurrencyConversion`), ми просто створюємо два декоратори.

### 3. Як можна комбінувати Composite та Decorator для створення складних та гнучких систем?
Ці патерни ідеально доповнюють один одного:
1. **Composite** будує структуру (ієрархію).
2. **Decorator** змінює поведінку будь-якого вузла цієї структури.
У моєму варіанті ми можемо задекорувати як окрему транзакцію (Leaf), так і цілий пакет (Composite). Наприклад, комісія може нараховуватися на весь пакет транзакцій одним декоратором, замість того, щоб додавати її до кожної транзакції окремо.



### 4. Наведіть приклад, коли використання Composite або Decorator є більш доцільним, ніж інші підходи.
* **Composite** доцільний при розробці графічних редакторів (групування фігур) або файлових систем, де операції (видалення, переміщення) мають однаково працювати як для одного файлу, так і для папки.
* **Decorator** доцільний, коли потрібно додати функціональність, яка не є основною для класу (наприклад, логування, шифрування, кешування), або коли неможливо використовувати наслідування (наприклад, клас позначений як `sealed`).
