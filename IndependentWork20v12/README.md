# Контрольні питання до самостійної роботи №20

### 1. Поясніть патерн Strategy. Як він дозволяє змінювати поведінку об’єкта під час виконання?
**Strategy (Стратегія)** — це патерн, який визначає сімейство схожих алгоритмів, інкапсулює кожен з них у окремий клас і робить їх взаємозамінними. 
Він дозволяє змінювати поведінку об'єкта в рантаймі завдяки **композиції**: замість того, щоб жорстко прописувати логіку в класі через `if/else` або `switch`, клас (Контекст) тримає посилання на інтерфейс стратегії. Коли ми викликаємо `SetStrategy()`, ми просто підміняємо один об'єкт-алгоритм іншим.

### 2. Поясніть патерн Observer. Як він забезпечує слабке зв’зування між суб’єктом та спостерігачами?
**Observer (Спостерігач)** — патерн, що створює механізм підписки, який дозволяє одним об'єктам стежити за подіями в іншому об'єкті.
**Слабке зв'язування** забезпечується тим, що Суб'єкт (DataPublisher) не знає нічого про конкретні класи спостерігачів. Він знає лише те, що у них є метод, який відповідає певному підпису (делегату). Суб'єкт просто "кричить" про подію, а хто його слухає — йому байдуже.

### 3. Як події та делегати в C# використовуються для реалізації патерну Observer?
В C# патерн Observer вбудований на рівні мови:
*   **Делегат (наприклад, Action<T>)** визначає "контракт" або підпис методу, який може бути викликаний.
*   **Подія (event)** — це захищена обгортка над делегатом, яка дозволяє зовнішнім класам тільки підписуватися (`+=`) або відписуватися (`-=`), але не дозволяє викликати подію напряму або очистити список підписників. Це і є ідеальна реалізація механізму сповіщення.

### 4. Наведіть приклад, як комбінація Strategy та Observer може створити гнучку та розширювану систему.
Приклад: **Система онлайн-замовлень**.
1.  **Strategy** використовується для вибору методу оплати (Visa, PayPal, Crypto). Користувач може змінити спосіб оплати в будь-який момент перед натисканням кнопки.
2.  **Observer** використовується для сповіщення після успішної оплати: один спостерігач надсилає Email клієнту, другий — повідомлення на склад для пакування, третій — в аналітичний відділ.
Ви можете додати нову стратегію оплати або нового спостерігача (наприклад, SMS-сповіщення), не змінюючи код самого класу "Замовлення".
